# 04. ステップ3：LLM による重要度判定と3択生成

ステップ2の文字起こし結果（`transcript.json`）をローカル LLM（Ollama）に渡し、各文の **重要度（1〜3）** と、テロップ用の **要約版・インパクト重視版** の文言を作る。結果は UI に渡す最終データ `result.json` として保存する。

担当ファイル：`backend/core/llm_processor.py`（クラス `LLMProcessor`）

---

## 1. 入力と出力

### 入力（作業フォルダ `temp/{project_id}/` 内）

| ファイル | 必須 | 使いみち |
|---|---|---|
| `transcript.json` | ○ | 文の ID・時間・原文・信頼度（ステップ2の結果） |
| `silence_cut.json` | - | `result.json` の `source` と `silence_cut` を作る（ない場合は `null` にする） |

### 出力：`result.json`

`GET /projects/{id}/result` のレスポンスと同じ形（`01_api_schema.md` の 4.5）。

```json
{
  "project_id": "test",
  "source": { "file_name": "vlog_0929.mp4", "duration": 612.48, "width": 1920, "height": 1080, "fps": 29.97 },
  "silence_cut": { "enabled": true, "original_duration": 612.48, "cut_duration": 498.12, "removed_duration": 114.36, "kept_ranges": [] },
  "preview_url": "/api/v1/projects/test/media/preview",
  "llm": { "status": "ok", "model": "qwen2.5:7b", "failed_segments": 0, "message": null },
  "segments": [
    {
      "id": "seg_0001",
      "index": 0,
      "start": 0.0,
      "end": 2.48,
      "importance": 3,
      "variants": {
        "original": "えーと今日はですね新しいカメラを紹介していきたいと思います",
        "summary": "今日は新しいカメラを紹介します",
        "impact": "新カメラ、ついに解禁！"
      },
      "confidence": 0.92
    }
  ],
  "importance_summary": { "1": 38, "2": 71, "3": 24 }
}
```

- `project_id` は作業フォルダの名前を使う（API では UUID のフォルダ名になる）。
- `llm.status` の意味は `01_api_schema.md` の 4.5 を参照（`ok` / `partial` / `failed` / `disabled`）。

---

## 2. 処理の手順

1. `transcript.json` を読み込む（ない場合は `FILE_NOT_FOUND`）
2. `options.llm.enabled = false` なら、全文を既定値にして 7 へ
3. Ollama の `GET /api/tags` で、サーバーが起動しているか、モデルが取得済みかを確認する。だめなら全文を既定値にして 7 へ
4. 文を **20文ずつ**（`batch_size`）に分け、前後 **3文ずつ**（`context_size`）を文脈として添えて `POST /api/chat` に送る
5. 返ってきた JSON を1件ずつ検証する。足りない文・不正な文があれば、その文だけを **1回だけ** 送り直す
6. それでも結果が得られなかった文は既定値にする
7. `result.json` を保存し、結果のリストを返す

### 既定値（フォールバック）

`importance: 2`、`summary` と `impact` は `original` と同じ文。UI はこの状態でも普通に動く（3択はすべて同じ文になる）。

| 状況 | 動き |
|---|---|
| Ollama が起動していない（接続できない） | 全文を既定値にする。途中で落ちた場合は、残りの文を既定値にする |
| モデルが未取得 | 全文を既定値にする。`message` に `ollama pull` のコマンドを入れる |
| JSON として読めない・形が違う・時間切れ | その回の結果を捨てて1回だけ送り直す |
| 一部の文だけ不正（重要度が 1〜3 以外、文言が空など） | その文だけ送り直す |

---

## 3. Ollama の呼び出し

| 項目 | 値 |
|---|---|
| URL | `http://127.0.0.1:11434`（環境変数 `EDITAI_OLLAMA_URL` で変更できる） |
| エンドポイント | `POST /api/chat` |
| `model` | `qwen2.5:7b`（`options.llm.model`） |
| `format` | 下の JSON スキーマ（構造化出力。Ollama 0.5 以降が必要） |
| `stream` | `false` |
| `options.temperature` | `0.3`（言い換えに少しだけ幅を持たせつつ、判定は安定させる） |
| `options.num_ctx` | `8192`（20文＋文脈＋出力が収まる長さ） |
| `keep_alive` | `"10m"`（バッチの間にモデルがメモリから降ろされないように） |
| タイムアウト | 接続 5 秒、応答 300 秒（CPU だけの PC では1バッチに数分かかることがある） |

- `localhost` ではなく `127.0.0.1` を使う。Windows では `localhost` が先に IPv6（`::1`）で接続を試み、つながるまで待たされることがあるため。
- `format` に JSON スキーマを渡すと、Ollama がその形の JSON しか出力しないように制御してくれる。ただし中身（ID の対応や文言の質）までは保証されないので、Pydantic での検証は必ず行う。

### 出力の JSON スキーマ

```json
{
  "type": "object",
  "properties": {
    "results": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "id": { "type": "string" },
          "importance": { "type": "integer", "enum": [1, 2, 3] },
          "summary": { "type": "string" },
          "impact": { "type": "string" }
        },
        "required": ["id", "importance", "summary", "impact"]
      }
    }
  },
  "required": ["results"]
}
```

## 4. プロンプトの設計

### 4.1 方針

- **文脈と対象を分ける**：バッチの境目で話の流れが途切れないよう、前後の文を「文脈」として渡す。ただし文脈の文は評価させない（別のバッチで評価するため）。
- **重要度の基準を具体的に書く**：「重要そうな文」とだけ書くと、ほとんどの文が 2 か 3 になる。重要度 1 になる文の例（相づち・言い直し・つなぎの言葉）をはっきり示し、スライダーで絞り込んだときに効果が出るようにする。
- **事実を足させない**：インパクト重視版は誇張しやすいので、「原文にない事実や数値を足さない」と明記する。
- **例を1つ見せる**：7B クラスのモデルは、ルールの説明だけより例があるほうが形と長さが安定する。

### 4.2 システムプロンプト

```
あなたは日本語の動画編集アシスタントです。動画の文字起こしを読み、テロップ（字幕）用に各文を評価して書き換えます。

# 入力
- 「文脈（前）」「文脈（後）」：話の流れを理解するための前後の文です。評価はしません。
- 「対象」：評価する文です。各行は「ID: 本文」の形です。

# 対象の文ごとに出力する項目
1. importance（重要度）：1〜3 の整数
   - 3：話の要点・結論・新しい情報・驚きや笑いなど、視聴者に必ず見せたい文
   - 2：説明や補足など、内容のある普通の文
   - 1：相づち（「はい」「うん」）、言い直し、「えーと」などのつなぎ、あいさつだけの文など、内容がほとんどない文
2. summary（要約）：意味を変えずに、読みやすく短く整えた文
   - 「えー」「あのー」「まあ」などのつなぎの言葉と言い直しを取り除く
   - 必要なら句読点を付ける
   - 原文より長くしない
3. impact（インパクト重視）：視聴者の目を引く短いテロップ
   - 15 文字程度まで。体言止めや「！」を使ってよい
   - 原文にない事実や数値を足さない

# ルール
- 「対象」のすべての文について、同じ ID で1件ずつ、入力と同じ順番で返してください。
- 固有名詞や数値は原文のまま使ってください。
- 内容のない文は、summary と impact を原文と同じか、ごく短くしてかまいません。
- JSON だけを出力し、説明は書かないでください。

# 例
入力：
## 対象
seg_0001: えーと今日はですね新しいカメラを紹介していきたいと思います
seg_0002: まあ、はい

出力：
{"results": [
  {"id": "seg_0001", "importance": 3, "summary": "今日は新しいカメラを紹介します", "impact": "新カメラ、ついに解禁！"},
  {"id": "seg_0002", "importance": 1, "summary": "はい", "impact": "はい"}
]}
```

### 4.3 ユーザーメッセージ（バッチごとに作る）

```
## 文脈（前）
seg_0018: そしたら店員さんがこっちのほうが軽いですよって
seg_0019: 持たせてもらったんですけど

## 対象
seg_0021: いやこれほんとに軽くて
seg_0022: 片手で一日中持っててもまったく疲れないんですよ
...

## 文脈（後）
seg_0041: で次にレンズの話なんですけど
```

- 文脈がない場合（最初・最後のバッチ）は、その見出しごと省く。
- 送り直すときは、足りなかった文だけを「対象」にし、文脈は元のバッチと同じものを使う。

---

## 5. 結果の検証（Pydantic）

- JSON 全体が読めない、または `results` が配列でない → その回は失敗として送り直す
- `results` の各要素は1件ずつ検証し、不正な要素だけを捨てる（1件の不正でバッチ全体を捨てない）
  - `importance` は 1〜3 の整数（`"3"` のような文字列は数値に変換して受け付ける）
  - `summary` / `impact` は前後の空白を除いて1文字以上
  - `id` が「対象」に含まれていない要素は捨てる。同じ ID が2回出たときは最初のものを使う

---

## 6. 進捗・ログ・中断

- 進捗は「処理が終わった文の数 ÷ 全体の文の数」（0〜100）。API はこれを `steps[].progress`（`llm_processing`）に入れる。
- ログ（ロガー名 `core.llm_processor`）：開始時の文の数とバッチ数、バッチごとの結果と所要時間、送り直し、フォールバックの理由、完了時の `llm.status` を記録する。
- 中断はバッチの切り替わりで確認する（Ollama への1回の問い合わせの途中では止められない）。

---

## 7. エラー

LLM が原因の問題では処理を止めない（「2. 処理の手順」の既定値を使う）。止めるのは次の場合だけ。

| code | 発生条件 |
|---|---|
| `FILE_NOT_FOUND` | `transcript.json` がない（ステップ2が終わっていない） |
| `INTERNAL_ERROR` | `transcript.json` が壊れていて読めない |

---

## 8. 単体での動かし方

ステップ1・2を実行済みのフォルダを指定する。先に Ollama を起動し、`ollama pull qwen2.5:7b` でモデルを取得しておく。

```
cd backend
python -m core.llm_processor ../temp/test --model qwen2.5:7b
```

| オプション | 既定値 | 説明 |
|---|---|---|
| `--model` | `qwen2.5:7b` | Ollama のモデル名 |
| `--batch-size` | `20` | 1回に評価させる文の数 |
| `--url` | `http://127.0.0.1:11434` | Ollama の URL |
| `--disable` | - | LLM を使わず、全文を既定値にする（フォールバックの確認用） |

Ollama を止めた状態で実行すると、フォールバックの動き（`llm.status: failed`）を確認できる。

---

## 9. 今後の検討事項

- 重要度の偏り：実際の動画で 1・2・3 の割合を見て、偏りが強ければプロンプトに「3 は全体の 2〜3 割程度」のような目安を足す。
- インパクト重視版の文字数：テロップの横幅（フォントサイズ×文字数）と合わせて、上限を決め直す。

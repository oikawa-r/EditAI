いまの実装と、`docs/app-spec.md` の画面仕様を、分野とブロックに分けて書いたもの。  
状態は次の4つ。

| 状態 | 意味 |
|---|---|
| 動作する | 画面または処理がつながり、その操作の結果まで出る |
| 見た目だけ | 画面はある。押してもログを出すか、中身は動かない |
| 旧画面に残る | 非表示の古い編集画面と `frontend/main.js` に処理がある。いまの編集画面からは使わない |

## 1. バックエンド

ローカルの Python 処理。ユーザー確認済みのエンジンは、無音カット、文字起こし、LLM、テロップ焼き込み。API サーバーは一通りつなぎ、解析から書き出しまで通した。

### 1.1 無音カット

- 状態: 動作する
- 場所: `backend/core/silence_cutter.py`、仕様は `docs/02_silence_cut.md`
- 内容: 音声抽出、Silero VAD、発話区間の結合、`cut.mp4` と `silence_cut.json`（`kept_ranges`）の出力
- 確認: `python -m core.silence_cutter` で `audio.wav`、`cut.mp4`、`silence_cut.json` が出るところまで確認済み

### 1.2 文字起こし

- 状態: 動作する
- 場所: `backend/core/transcriber.py`、仕様は `docs/03_transcription.md`
- 内容: 無音カット後の `cut.mp4` を faster-whisper で文字起こしし、`transcript.json` に保存する。モデル未指定時の既定は重いので、API 経由の開始時は `small` を送る
- 確認: `transcript.json` の出力まで確認済み

### 1.3 重要度と3パターンの文言

- 状態: 動作する
- 場所: `backend/core/llm_processor.py`、仕様は `docs/04_llm_processing.md`
- 内容: Ollama（`qwen2.5:7b`）へ文を渡し、重要度 1〜3 と、原文・要約・インパクトの3文言を JSON で受ける。失敗しても解析全体は止めず、重要度 2 と原文のままを入れる
- 確認: `result.json` まで確認済み

### 1.4 テロップの焼き込み

- 状態: 動作する
- 場所: `backend/core/sub_exporter.py`、仕様は `docs/06_export_video.md`
- 内容: スタイルと文から ASS を作り、FFmpeg で `cut.mp4` に焼き込む。Windows では `.ass` のあるフォルダをカレントにしてファイル名だけを渡す
- 確認: `output.mp4` まで確認済み

### 1.5 API サーバー

- 状態: 動作する
- 場所: `backend/api/server.py`、起動は `backend/main.py`（`127.0.0.1:8765`）
- つながっている入口:
  - `GET /health`
  - プロジェクトの作成、状態取得、中断、結果取得、プレビュー用動画
  - 書き出しの開始、状態、ダウンロード
  - スタイルプリセットの一覧、作成、更新、削除
- ジョブは1本ずつ。状態はメモリと `temp/{id}/status.json`。サーバー再起動で途中のジョブは失敗になる
- 確認: `/health`、解析の状態ポーリング、`/result`、書き出しまで通した
- 未着手: 編集後のタイムライン（トラックとクリップの配列）を受け取る入口。無音カットの範囲を画面から書き換える入口

## 3. 状態管理

仕様（`docs/app-spec.md` の「状態管理要件」）では、次を1つの情報源にする。

- プロジェクトデータ: 解像度、フレームレート、トラック配列、その中のクリップ配列（`id`、`type`、`startTime`、`duration`、`sourceUrl`、座標、スケール、回転）
- `currentTime` と `selectedClipId`
- キャンバス操作とプロパティ数値は、同じクリップデータを直接更新する
- プロジェクトデータの履歴を残し、元に戻せるようにする

プロジェクトの正は `state.project`（幅・高さ・fps・トラック配列）。クリップは `id`、`type`、`name`、`startTime`、`duration`、`sourceUrl`、`kept`、`x`、`y`、`scale`、`rotation` を持つ。時刻の基準はソース動画側。

| 項目 | 状態 | いまの実体 |
|---|---|---|
| グローバルな `state` オブジェクト | 動作する | `frontend/main.js` の `state`。接続、解析中、`project`、`currentTime`、`selectedClipId`、テロップ文、スタイル |
| `currentTime` | 動作する | プレビューの `#preview-monitor` と再生ヘッドが双方向に追従する。再生中もヘッドが進む |
| `selectedClipId` | 動作する | クリックで1件選ぶ。分割・削除・プロパティ編集がこの ID を見る |
| トラックとクリップの階層 | 動作する | 初期は映像1〜3、音声1。映像1が手前。クリップの移動・上書き・トリム・分割・削除ができる |
| 解像度と fps | 動作する | 初期値は 1920×1080 / 30。解析結果で上書きする。スタート画面やヘッダーからの変更はない |
| Undo の履歴 | 仕様だけ | 履歴配列はない |
| ペイン間のリアルタイム同期 | 一部動作する | 再生位置はプレビューとタイムラインで揃う。選択中の動画・画像のスケール・座標・回転は、プロパティ欄とプレビューの変形へすぐ反映する |

タイムラインの「分割」「削除」は、クリップ未選択のとき押せない。カットとテロップのボタンは、解析中以外は押せる。

| ブロック | 状態 | 押したときの動き |
|---|---|---|

## 6. 専用サブ画面
